# 프론트엔드 기능 시험

## 실행

현재 작업 브랜치는 `feat/openapi-frontend`다. 기존 `test/frontend-api-integration`을 이름만 변경했다. 작업 시작 시 브랜치는 `develop`의 `8e7fbc5`와 같았고 작업 트리는 비어 있었다. 수정 범위는 `mobile/`이다. 커밋·푸시·머지·PR·배포는 실행하지 않았다.

Node 22 이상과 pnpm 10 이상을 사용한다.

```sh
cd mobile
pnpm install --frozen-lockfile
# .env.example을 .env로 복사하고 주소 설정
pnpm start
# 또는 pnpm web
```

주소는 `EXPO_PUBLIC_API_URL` 하나로 설정한다. 예: `EXPO_PUBLIC_API_URL=http://localhost:8080`. 명세용 Client는 이 주소에 `/api/v1`을 붙인다. 이미 `/api/v1`로 끝나면 중복하지 않는다. 환경변수를 바꾼 뒤 Metro를 재시작한다. 실기기는 PC의 LAN 주소를 사용한다.

현재 배포 개발 서버 `https://api-chorong-dev.bawibase.com`의 공개 OpenAPI는 PDF와 다르다. PDF의 `/api/v1` 경로가 준비된 서버 주소를 사용해야 한다. 기존 앱 API는 `/api/` 계약을 쓰며 `src/lib/`에 남겨 두었다. 명세 API는 `src/integration/`의 별도 세션과 Client를 쓴다. 두 로그인 상태는 공유하지 않는다.

Expo 57, React Native 0.86, React 19, TypeScript 6, Expo Router, Axios를 유지했다. 승인받은 `expo-secure-store`만 추가했다. 서버·DB·백엔드는 수정하지 않았다.

## 사용자 화면 시험 순서

로그인 없이 화면 조작을 확인하려면 홈의 `로그인 없이 UI 미리보기` 또는 더보기의 `UI 미리보기`를 연다. 로컬 화면 데이터로 홈 메뉴 토글, 코스→레슨 이동, 세로 스와이프·답안 선택을 시험한다. 꾸미기·상점은 추후 구현 안내만 표시한다. 이 경로는 서버 요청을 보내지 않으며 채점·구매·저장 성공을 표시하지 않는다. 실제 API 검증은 아래 순서로 별도 실행한다.

1. 홈에서 `로그인하기`를 눌러 게스트 계정을 만든다. 웹에는 명세의 WEB 플랫폼 값이 없어 게스트 버튼을 비활성화한다. 실제 플랫폼 검증은 네이티브에서 한다.
2. 홈 우측 상단 `+`를 눌러 인벤토리·상점·우주 탐험 메뉴를 펼친다. 항목 선택 뒤 메뉴가 닫히는지 확인한다.
3. 학습 탭에서 코스 목록 → 코스 상세 → 레슨 상세 → `시작하기`로 이동한다. 서버가 준 `resumeContentId`와 잠금·선행 복습 상태를 확인한다.
4. 학습 화면에서 위로 넘겨 다음 콘텐츠, 아래로 넘겨 이전 콘텐츠로 이동한다. 콘텐츠 완료 전에는 다음 페이지로 진행하지 않는다. 퀴즈는 답을 제출하고 채점 결과를 받은 뒤 오답이어도 `학습 완료`를 누를 수 있다. 마지막 콘텐츠 뒤 레슨 완료와 보상을 확인한다. 다시 하기에는 완료·보상 API를 보내지 않는다.
5. 홈의 `복습하기`에서 서버 문제를 불러와 답안을 제출한다. 빈 목록은 그대로 표시한다. `온보딩`에서는 시작·퀴즈·완료 또는 건너뛰기를 시험한다.
6. 홈에서 인벤토리·상점 메뉴를 눌러 추후 구현 안내가 표시되는지 확인한다. 이 화면은 배치·구매·저장 요청을 보내지 않는다.
7. 소셜 탭에서 공개 목록과 다음 페이지를 조회하고 다른 우주를 방문한다. 좋아요·취소·신고를 시험한다. 회원 전용 기능은 게스트에게 계정 안내를 표시한다.
8. 더보기 → 개발자 도구 → 기능 테스트/요청 기록에서 API 번호, Method, Endpoint, 상태, 응답 시간, 에러 코드, 마스킹된 요청·응답을 확인한다. 일반 사용자 화면에는 이 정보를 표시하지 않는다.

홈의 방 모양은 중앙에 고정된다. 우측 상단 메뉴는 방과 아래 콘텐츠의 위치를 바꾸지 않고 겹쳐 펼쳐진다. 꾸미기·상점 편집 UI는 레이아웃을 다시 정한 뒤 구현한다.

## 계약과 제한

| 항목        | 확인할 사항                                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 객관식·순서 | PDF는 `options` 내부 구조와 index·order 의미를 확정하지 않는다. 화면은 `{index,label}` 선택지에만 입력을 연결하고 다른 형태는 명세 확인 대기로 표시한다.        |
| 소셜 차단   | 방문·목록 응답에 소유자 `userId`가 없어 사용자 화면에서 차단 대상을 결정할 수 없다. 개발 테스트 화면의 수동 ID 입력만 유지한다.                                 |
| 구매        | API-903과 API-702 호출 함수는 남겨 두었다. 일반 꾸미기·상점 화면에서는 호출하지 않는다.                                                                         |
| OAuth·Push  | 플랫폼 SDK 자격 증명과 실기기 설정이 없다. 개발 테스트 화면에서 수동 자격 증명/토큰 요청만 가능하다.                                                            |
| 미구현      | 하우징 이름 변경 UI와 아바타 설정(API-704)은 호출하지 않는다. 공개 설정(API-703)은 우주선 관리와 탐색 화면에서 호출한다.                                        |
| 브라우저    | 토큰은 메모리에만 남아 새로고침 시 로그인해야 한다. UUID는 localStorage에 보관한다. CORS에서 Authorization·Idempotency-Key와 X-Request-Id 노출을 확인해야 한다. |

네이티브는 SecureStore에 서버 주소별 토큰과 UUID를 저장한다. 앱 재시작 시 갱신과 내 정보 조회로 세션을 복원한다. 진단 기록은 메모리에 최대 30개만 보관하고 토큰·비밀번호·이메일·UUID를 숨긴다. 로그인·구매·보상·완료는 서버를 실제로 변경하므로 테스트 계정을 사용한다.

## 코드 경계

`src/integration/client.ts`는 HTTP·인증·재시도·진단을 처리한다. `catalog.ts`와 `api.ts`는 명세 경로와 호출 함수를 정의한다. `models.ts`와 `schema.ts`는 응답을 검사한다. `user/`는 교체 가능한 일반 화면이다. `screens/`와 `app/integration/`은 개발자 기능 시험 화면이다. `app/(tabs)/`는 사용자 진입점이다.

## 검증

TypeScript 검사와 Prettier 검사, 웹 34개 정적 라우트, Android Hermes 번들이 통과했다. 기존 인증 13개·퀴즈 27개와 명세 Client 17개 테스트가 통과했다. Windows 샌드박스는 `node --test` 자식 프로세스를 막아 컴파일 뒤 각 테스트 파일을 `node`로 직접 실행했다. 실제 PDF 서버의 계정·학습·구매·배치 E2E는 검증하지 못했다. 배포 서버의 `/api/health`와 `/api-docs`만 읽기 확인했다. 브라우저 클릭 자동화 도구가 현재 Chrome URL을 확인하지 못해 시각·제스처 조작은 미검증이다. iOS·Android 실기기, SecureStore·푸시·OAuth SDK도 미검증이다.
